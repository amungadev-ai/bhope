# Beacon of Hope 0.2

Daily devotionals, the Bible, and the notebook stay free. Paid extras remain a later phase. Inspirations starts with a deliberate empty state until editors add real videos.

## Update an existing Windows checkout

Stop the running Expo server with Ctrl+C, then run in PowerShell:

```powershell
Set-Location "$HOME\Projects\bhope"
git pull origin main
npm ci
Set-Location .\apps\mobile
npx expo start --clear
```

Open the QR code in the current Android Expo Go app. The entry is now `apps/mobile/index.ts`, and screens use direct React Navigation 7. Existing notes use the same `beacon-of-hope.db`; a Bible refresh changes only the imported verse library. Avoid clearing Expo Go data or uninstalling it when testing an update. Export important notes as a backup.

No API is required for local reading or notebook testing. A configured API is needed for account actions, AI, new editorial content, and payments. Your full Bible import remains local and excluded from Git; a fresh public checkout uses the labelled sample.

## Try these interactions

1. Open the drawer from the header and explore account, saved verses, giving, history, preferences, and the original TikTok profile link.
2. Search the Bible for `john 1: 1-10`, `jhon 1:1-10`, or `Yohana 3:16`. A normal verse tap focuses it. Long press for explicit save, copy, share, and note actions.
3. Create a sermon note. Try heading/paragraph, underline, both list types, and checkboxes. Type a reference within a sentence and tap its blue text. Long press a reference or inserted passage for actions.
4. Use the visible Bible button in the toolbar. Select a verse, choose “Add passage and return to note,” and check that the original note remains open. Save, leave, reopen, and verify formatting and checkbox state.
5. Open reflection tools using the small sparkles icon. The app explains what goes to DeepSeek and requests sign-in/consent there.
6. Open Inspirations. It stays empty until a video is published in the studio. Both the curated video feed and main TikTok profile link are available.
7. Open Giving. Review amount and method in the bottom sheet. Submission stays disabled without merchant configuration. Nothing in this update charges money automatically.

## Release checks

Automated coverage includes shared parsing/URL validation, content authorization, note ownership and rich HTML round trips, payment initialization/idempotency, exact amount verification, signed/replayed callbacks, M-Pesa server queries, and finance permissions. Production API/studio builds, mobile typecheck/lint, an Android Hermes export, and browser interaction checks are part of validation.

Physical Android keyboard/selection/long-press behavior and real provider/hosting behavior still need on-device and sandbox verification. Cloud note sync, email verification/password reset, account deletion, reminders, and published funding reports are separate next milestones. A public release also needs edition permissions, reviewed interdenominational editorial guidelines, accessibility checks, and privacy/contact information.
