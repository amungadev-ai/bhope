# Beacon of Hope 0.5

## Collapsible formatting sidebar

The formatting control shares a row with the sermon/reflection details toggle. Opening it shows the ten editing tools in a floating vertical sidebar over the writing area. The sidebar scrolls on shorter screens; opening or closing it does not resize or reflow the note. The rich editor remains mounted and keeps the selected words, so formatting applies to the intended selection.

## Edit and read detected references

Blue reference text is editable text. Tap between characters to place the caret and type; an ordinary tap no longer opens the passage sheet or dismisses the keyboard. Hold the reference to read its passage and use the existing actions. On desktop, right click or Alt+Enter at the reference also opens it. Ordinary Enter continues editing the note.

Reference detection waits until an input-method composition ends before rebuilding highlights. Touch movement cancels the passage hold, and a little stationary-touch movement is tolerated. Existing rich notes load through the same sanitizer and receive the updated behaviour without changing their stored content structure.

## Floating AI action

The reflection-tools button starts at the bottom right of the writing area. Tap it to open the usual AI options, sign-in/consent disclosure, and trial/plan checks. Drag it to move it inside the editor; moving never initiates AI assistance or opens the sheet.

Its position follows the available writing area as the sidebar opens/closes or the keyboard changes height. The control cannot be dragged outside that area. Native accessibility actions include moving it back to the bottom right. New editor instances start at the default position.

## Update

Stop Expo with Ctrl+C, then run:

```powershell
Set-Location "$HOME\Projects\bhope"
git pull origin main
Set-Location .\apps\mobile
npx expo start --clear
```

No dependencies or migrations were added. Browser interaction checks cover cursor placement inside detected references, editing/detection, passage holds, composition events, sidebar selection preservation, drag/tap separation, bounds after resizing, and saved content. Physical Android keyboard, selection handles, and dragging still need on-phone review.

## 0.5.1 spacing refinements

Format and note details now sit inline. The editor uses narrower horizontal padding, and the formatting sidebar is 60 px wide with 44 px tool targets. The italic glyph uses the already-loaded Lora italic font in a padded text box, avoiding synthetic-italic clipping. The draggable AI bubble is reduced from 54 px to 46 px, with a 20 px icon and its original 54 px touch area. No dependencies or data changes are required.

## 0.5.2 floating sidebar and typing fixes

The sidebar floats above the editor at its left edge and fits its tools, scrolling within the remaining space on shorter screens. The editor and its horizontal padding stay the same width when the sidebar opens; selection remains available for formatting.

Verse highlighting now bookmarks each selection endpoint within its own paragraph or list item and counts line breaks, including empty paragraphs. Enter keeps the caret on its new line instead of pulling it back after the highlight delay. Highlighting preserves child structure when unwrapping references and leaves plain text alone when there are no references to decorate. Normal Enter, Shift+Enter, list continuation, and composition retain browser editing behavior.

The shared navigation helper uses `CommonActions.navigate(name, params)` to remove the deprecated object-argument warning. No new dependencies or database changes.
